# GamerStore — Платформа цифровых товаров для геймеров

Реализован production-ready фуллстек проект на **TypeScript (strict mode)** с чистой модульной архитектурой, строгой гарантией **однократной выдачи цифровых товаров (Exactly-Once Delivery)** в условиях параллельных гонок (race conditions), восстановлением после сбоев и интеграцией состязательных сценариев тестирования.

## 2. Ключевые решения: как обеспечена однократная выдача

1. **Дедупликация входящих вебхуков по `event_id`**:
   - Реализован реестр обработанных событий `processedEvents`. При повторном поступлении вебхука с тем же `event_id` система возвращает статус `ignored` и кэшированный ответ, исключая повторное списание ключа.
2. **Посегментная изоляция конкурентности (`KeyedMutex`)**:
   - Критические операции над каждым заказом (`order_id`) и каждым промокодом (`promo_code`) сериализуются асинхронным мьютексом. 50 одновременных вебхуков по одному заказу выстраиваются в очередь — первый выполняет выдачу, остальные 49 видят терминальный статус и отклоняются как дубликаты.
3. **Конечный автомат состояний заказа (State Machine)**:
   - Жизненный цикл: `created -> paid -> delivering -> delivered`.
   - Если заказ достиг статуса `delivered`, любая повторная оплата или повторная ручная выдача идемпотентно возвращают ранее выданный ключ без расхода остатков.
4. **Атомарное списание из пула ключей**:
   - Выбор ключа и привязка (`isAssigned = true, assignedToOrderId = order_id, assignedAt = now`) выполняются строго внутри критической секции. Один ключ принципиально не может быть выдан двум разным заказам.
5. **Обработка событий не по порядку (Out-of-Order Delivery)**:
   - Если вебхук оплаты пришел раньше, чем завершилось создание заказа, платеж сохраняется в буфере `pendingPayments`. В момент создания заказа он немедленно активируется и выдает товар без потерь.
6. **Восстановление при исчерпании остатков (`out_of_stock`)**:
   - При пустом пуле заказ переходит в безопасное восстановимое состояние `out_of_stock`. В панели администратора доступна безопасная ручная выдача (`reissue`), которая после пополнения пула выдает ровно 1 ключ.
7. **Поставщики A и B с сохранением кода по `request_id` (Ловушка «таймаут ≠ отказ»)**:
   - При таймауте поставщика A повторный вызов с тем же `request_id` гарантированно возвращает тот же код, не списывая новый. При постоянной ошибке 5xx выполняется прозрачный fallback на резервного поставщика B.
8. **Атомарные промокоды (Этап 4)**:
   - Серверный расчет скидки (процент или фиксированная сумма) без доверия клиенту.
   - Лимит `currentUses < maxUses` проверяется и инкрементируется атомарно под мьютексом (из 20 параллельных запросов на `LIMIT3` скидку получают ровно 3 заказа, остальные 17 отклоняются с ошибкой лимита).

## 3. Как воспроизвести проверку гонок

Проверку состязательных сценариев можно запустить тремя независимыми способами:

### Способ 1. Автоматические тесты Jest (12 тестов)
```bash
npm test
```
Запускает 4 тест-сьюта:
- `tests/integration/concurrency.test.ts` — 50 параллельных вебхуков, out-of-order связка, уникальность ключей для 10 параллельных заказов.
- `tests/unit/idempotency.test.ts` — дедупликация `event_id`, идемпотентный `reissue`.
- `tests/unit/delivery.test.ts` — восстановление из `out_of_stock`, fallback поставщика B, сохранение кода по `request_id`.
- `tests/unit/promo.test.ts` — конкурентные гонки за промокод с лимитом N.

### Способ 2. Автономный CLI-скрипт проверки сценариев ТЗ
```bash
npm run test:concurrency
```
Выводит пошаговый отчет с метриками времени и подтверждением `PASSED` для всех 5 состязательных сценариев ТЗ.

### Способ 3. Интерактивный Live Runner в браузере
1. Откройте [https://test-task-fullstack-razrabotchik-mu.vercel.app](https://test-task-fullstack-razrabotchik-mu.vercel.app).
2. Нажмите кнопку **«Стресс-тест гонок»** в шапке сайта.
3. Нажмите **«Запустить тесты»** — браузер в реальном времени выполнит параллельные запросы к API и покажет детализированные метрики (число принятых/отклоненных вебхуков, списанные ключи, время в мс).

## 4. Что реализовано по ТЗ

1. **Витрина (Этап 1)**:
   - **Интерактивный элемент 1 (Баннер-карусель)**: автоматическая смена слайдов каждые 5 сек, кнопки стрелок «вперед/назад», кликабельные индикаторы-точки.
   - **Интерактивный элемент 2 (Кнопка «Каталог»)**: открывает выпадающее меню с категориями товаров, повторный клик или клик вне меню закрывает меню.
   - **Интерактивный элемент 3 (Блок пополнения Steam)**: интерактивный переключатель валют ($/₸/₽) с активным состоянием, ввод логина, выбор номиналов (500 ₽, 1000 ₽, 2500 ₽), поле промокода с проверкой, кнопка покупки.
   - **Интерактивный элемент 4 (Ряд иконок сервисов)**: Steam, Telegram, Roblox, Discord, PlayStation, Xbox, Spotify, YouTube с плавным выделением при наведении и фильтрацией.
   - **Интерактивный элемент 5 (Карточки товаров)**: плавный подъем, акцент границы и тень при наведении, кнопка «Купить».
2. **Флоу заказа и оплаты**:
   - Создание заказа, эмуляция оплаты (кнопки успешной и неуспешной оплаты, отправка 50 одновременных вебхуков, повтор `event_id`), вывод выданного ключа с кнопкой копирования в буфер.
3. **Панель управления и сбоев (Этап 3)**:
   - Доступна по адресу `/admin` или по кнопке «Админка» в шапке.
   - Список заказов с фильтрацией («Все», «Оплачен, но не выдан», «Выдано»).
   - Кнопка безопасной ручной повторной выдачи (`reissue`).
   - Мониторинг остатков пула и форма пополнения ключей.
   - Интерактивные ползунки симуляции сбоев поставщиков (процент 5xx ошибок и таймаутов).
4. **Контейнеризация и сборка**:

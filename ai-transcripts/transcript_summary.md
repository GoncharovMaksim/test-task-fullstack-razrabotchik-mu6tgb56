# Лог этапов проектирования и решения задачи

## 1. Постановка задачи
- Разработка production-ready цифрового магазина (ключи, пополнения, подписки, гифт-карты).
- Ключевой фокус: **однократная выдача ключа (exactly-once delivery)** под параллельными гонками и **восстановление после сбоев (recoverability)**.
- 4 этапа ТЗ:
  1. Витрина (шапка, баннер-карусель, ряд иконок сервисов, пополнение Steam, карточки товаров, базовый флоу покупки и выдачи).
  2. Однократная выдача под гонками (50 параллельных вебхуков, дедупликация `event_id`, out-of-order доставка).
  3. Сбои и восстановление (исчерпание пула -> статус `out_of_stock`, безопасный идемпотентный ручной `reissue` после пополнения, симуляция поставщиков A и B с fallback и сохранением кода по `request_id`).
  4. Промокод с лимитом N под параллельными запросами (серверный расчет скидки, атомарная фиксация использования).

## 2. Архитектура решения
- **Стек**: Next.js 14 (App Router), TypeScript (strict mode), Tailwind CSS, Lucide Icons, Jest, ts-jest, Docker, Docker Compose.
- **Слой данных и изоляция гонок**:
  - `KeyedMutex`: асинхронный мьютекс с изоляцией по ключу (`order_id`, `promo_code`).
  - `AppStore`: транзакционный стор в памяти, обеспечивающий мгновенные проверки, отсутствие race condition и поддержку работы в serverless Vercel среде без внешних блокирующих зависимостей.
  - `PaymentService`: проверка `processedEvents` по `event_id` (идемпотентность), буфер `pendingPayments` для out-of-order событий, атомарный переход состояний заказа.
  - `DeliveryService`: изолированное списание ключа (один ключ никогда не уходит в 2 заказа), поддержка поставщиков A (с 5xx и таймаутами) и B (резервный fallback), переход в `out_of_stock` / `delivery_failed`, безопасный повторный `reissue`.
  - `PromoService`: серверный расчет скидки (процент / фиксированная сумма), атомарная проверка и инкремент счетчика `currentUses < maxUses`.

## 3. Этапы тестирования
- **Unit & Integration Tests (Jest)**:
  - `tests/integration/concurrency.test.ts`: 50 параллельных вебхуков на 1 заказ (ровно 1 успех, 49 дублей проигнорировано, списан ровно 1 ключ); доставка при приходе вебхука раньше создания заказа; уникальность ключей при одновременной покупке 10 товаров.
  - `tests/unit/idempotency.test.ts`: повтор с тем же `event_id`; повторная выдача на уже выданный заказ (0 новых ключей списано).
  - `tests/unit/delivery.test.ts`: пустой пул -> `out_of_stock` -> пополнение -> `reissue`; сбой поставщика A -> fallback на поставщика B; сохранение кода по `request_id` при таймауте.
  - `tests/unit/promo.test.ts`: гонки промокода LIMIT3 (лимит 3 под 20 параллельными запросами -> ровно 3 успеха, 17 отказов).
- **CLI Runner**: `npm run test:concurrency` (запуск через `tsx scripts/test-concurrency.ts`).
- **Интерактивный UI Runner**: модальное окно «Стресс-тест гонок» прямо в браузере с отображением времени в мс и статусов по каждому сценарию.
